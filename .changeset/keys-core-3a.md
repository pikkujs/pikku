'@pikku/core': patch
---

New `@pikku/core/keys` subpath: the reference key service for `defineKeyPair` declarations. `createLocalKeyService` signs, verifies, seals-open, rotates, promotes, retires and revokes keys over a `KeyStore` ledger, with the private half in custody `secret`, `file`, `wrapped` or `external`. `signer()` returns a handle that fixes kid, alg and version and re-checks the version status on every sign. Names are `signedFormat: "domain"` by default (signed bytes are `domain || 0x00 || data`, exported as `prefixWithDomain`) or `"jws"` (`signJws` writes `alg` and `kid` from the handle); the wrong form throws `DomainPolicyError`. Custody `secret` is refused on `LocalSecretService` and on any service that does not declare `durable`. `@pikku/core/keys/file` adds `FileKeyStore` and `FileCustody` (mode 0600; Node only, a server-tier subpath); `@pikku/core/keys` uses WebCrypto only. Nothing in core's other entry points imports it, so an app that does not use it bundles none of it. `@pikku/core/keypair` gains the `KeyService`, `KeyStore` and related interfaces and the `KeyUnavailableError`, `KeyRetiredError`, `KeyCustodyLostError`, `KeyRotatedError` and `DomainPolicyError` errors; `@pikku/core/hmac` gains `importSpkiVerifyKey` and `verifySpkiSignature`; `okpThumbprint` also accepts X25519 keys.

Core API notes: `KeySigner` has a required `signedFormat` (`signJws` refuses a handle from a domain name). `@pikku/core/services` also exports `spkiToDer`, `base64ToBytes` and `bytesToBase64` (the strict, canonical helpers; now in `utils/base64`). `importSpkiVerifyKey` takes an optional hash and returns extractable public keys, and `verifyPublicKeySignature` now reads SPKI through `spkiToDer`: base64url keys and PEM armour other than `PUBLIC KEY` no longer verify. `verify` with `historical: true` accepts retired keys but never revoked ones (`revoke` records `metadata.revokedAt`).
