# Decisions

A rule that was chosen, and what it rules out.

<!-- pikku:knowledge-index -->
- [A missing roles file never reads as zero declared roles](a-missing-roles-file-never-reads-as-zero-declared-roles.md) — loadDeclaredRoles returns null on a missing or malformed roles meta file, so prune cannot treat a read failure as an empty declaration and wipe system roles
- [A native app belongs to a frontend](a-native-app-belongs-to-a-frontend.md) — `frontends.<name>.native` makes a frontend installable; its Tauri project lives at `<cwd>/src-tauri`, is committed, and holds nothing specific to the machine that generated it
- [A platform scenario step is declared on the default surface only, and the catalogue exclusion lives in core](a-platform-scenario-step-is-declared-default-surface-only.md) — The pikkuPlatformScenarioStep wiring sets surfaces to default and does nothing else about virtual users; keeping it out of a virtual user's catalogue is enforced by core derivation
- [A scenario run refuses every internal RPC, workflow start and agent call that is not made as a virtual user](a-scenario-run-refuses-every-internal-call-that-is-not-made-as-a-virtual-user.md) — The CLI scenario runner passes a guard RPC that throws on invoke, remote, exposed, rpcWithWire, startWorkflow and the agent methods, so app calls in a scenario go out as a virtual user over HTTP
- [A virtual user belongs to one app and an audience gets one app](a-virtual-user-belongs-to-one-app-and-an-audience-gets-one-app.md) — The app scaffold refuses a new app for an audience another app already serves, and refuses a virtual user that already belongs to a different app
- [A 401 or 403 from pikku virtual-user rpc prints the virtual user's declared roles and exits 1](a-virtual-user-rpc-refusal-prints-the-roles-the-virtual-user-declares.md) — The command reports a refused call with the roles the virtual user declares in code, not the roles the server holds, and returns instead of throwing
- [pikku virtual-user rpc refuses a function that is not exposed, before it signs in](a-virtual-user-rpc-refuses-a-function-that-is-not-exposed.md) — The virtual-user rpc command checks the RPC is exposed before it mints a sign-in statement or signs anyone in
- [A virtual user scaffold refuses to generate when no virtual users are declared](a-virtual-user-scaffold-refuses-to-generate-with-no-virtual-users.md) — With scaffold.virtualUser enabled, codegen throws instead of emitting virtual-user RPCs, because the generated functions sign in as a declared virtual user and an empty set has nobody to run
- [An addon's override keys count as grants in the deploy manifest](addon-override-keys-count-as-secret-grants.md) — The analyzer merges an addon's grant list with the keys of its overrides, and lists addons with an unscoped global secret or credential apart from scoped ones
- [An addon's screens are granted exactly the union of its own functions scopes](addon-screen-scopes-are-the-union-of-its-function-scopes.md) — The screens manifest scopes are the sorted, de-duplicated union of the scopes on the addon's functions, and the screen file does not take a hand-written list
- [Adding an app writes the new app onto its virtual users only after the refusal and declaration checks pass](an-app-is-given-its-virtual-users-after-the-refusal-checks.md) — The app-new command refuses on the scaffold rules and on undeclared virtual users, and only then records the app on each named virtual user in source
- [Analytics ingest is sessionless and takes identity from the session, never the body](analytics-ingest-is-sessionless-with-identity-from-the-session.md) — The generated analytics ingest route is auth false, and the record call receives only the event and client time, while core stamps the user from the session
- [The app scope root is reserved and derived from virtual users](app-scope-root-is-reserved-and-derived-from-virtual-users.md) — The scopes generator adds an app tree built from virtual user app fields and refuses any declared scope with the same root, and addon scope trees are stamped with their addon as origin
- [App code imports only core services from core directly and reaches the rest through generated leaves](apps-import-only-core-services-directly.md) — The core import check reports every @pikku/core import except @pikku/core/services, and suggests the generated leaf for subpaths that have one
- [Auth schema checks trigger on any betterAuth Session middleware, not the literal name](auth-checks-match-any-better-auth-session-middleware.md) — hasAuthSessionMiddleware matches the regex betterAuth followed by any word and Session against the middleware groups, so the stateless variant also enables the auth checks
- [Auth wiring is generated from the declared pikkuBetterAuth definition, not from the provider count](auth-wiring-is-generated-from-the-declared-better-auth-definition.md) — The auth generator writes the /auth wiring, secrets and session middleware whenever a pikkuBetterAuth definition exists, so credentials-only auth with no OAuth providers still gets its wiring
- [BETTER_AUTH_SECRET is always declared as a required secret](better-auth-secret-is-always-a-required-secret.md) — The generated auth secrets file declares BETTER_AUTH_SECRET without optional: true, so the platform collects it for every project that uses pikkuBetterAuth regardless of providers
- [The browser driver is checked before the first scenario starts](browser-driver-is-checked-before-the-first-scenario.md) — resolveScenarioBrowserProvider refuses to start when the driver is missing, has no appUrl, or lacks an app url for a virtual user's app, and hands the driver a statement mint
- [Feature flags for the caller are readable without sign-in and scoped flags follow the session](caller-feature-flags-are-readable-without-sign-in.md) — The generated featureFlagsForCaller function is auth false and resolves against the request's session, so a scoped flag is withheld from a caller who lacks its scope
- [CLI login is the RFC 8628 device grant](cli-login-is-the-device-grant.md) — pikku login requests a device code, shows it to the person, and polls the token endpoint; the token is enriched from get-session on a best-effort basis
- [CLI sessions live in one 0600 file, keyed by server URL](cli-session-is-one-0600-file-keyed-by-server-url.md) — Bearer tokens from pikku login are stored in ~/.pikku/session.json with owner-only permissions, one entry per normalized base URL
- [pikku validate warns when a better-auth config does not enable cookieCache](cloud-validate-warns-when-better-auth-has-no-cookie-cache.md) — The validator warns when a pikkuBetterAuth config has no enabled session cookieCache, since the full better-auth server is then bundled into every unit
- [Codegen makes a wildcard requirable only for a scope that has children, and never the bare star](codegen-makes-a-scope-wildcard-requirable-only-when-it-has-children.md) — The generated ScopeId union adds scope:* only for scopes with descendants and never emits a bare *, so a leaf's wildcard is not a requirement type
- [Column classification is read only from the annotations sidecar and flattened before lookup](column-classification-comes-only-from-the-annotations-sidecar.md) — loadAnnotations reads db/annotations.gen.json as the single source of column classification, with no SQL comment fallback, and flattens a schema-qualified map to bare table names
- [The console bearer token is granted the admin and pikku scope roots only](console-bearer-token-is-granted-two-scope-roots.md) — An external console authenticates with PIKKU_CONSOLE_TOKEN as a bearer, which resolves to a session with admin and pikku scopes, and the token is a no-op while the secret is unset
- [Console recordings stay behind sign-in even though the console route group is auth false](console-recordings-stay-behind-sign-in-in-an-open-group.md) — The generated console route group is auth false, but the metadata stream and scenario artifact routes set auth true, because recordings are of an application being used
- [Custom types are declared once and each typed map aliases them](custom-types-are-declared-once-and-aliased-by-each-typed-map.md) — The custom types are written to one shared outDir file with relative imports, and each typed map re-exports them as one-line aliases rather than through an export-from statement
- [pikku dev turns virtual user sign-in and quick login on, and pikku serve turns virtual user sign-in off](dev-and-serve-set-the-virtual-user-and-quick-login-switches-differently.md) — The CLI defaults PIKKU_DEV_QUICK_LOGIN to true for both commands, but only dev enables the virtual user sign-in gate, and serve clears it with a warning
- [The dev credential key survives restarts in a 0600 file](dev-credentials-key-survives-restarts-in-a-0600-file.md) — pikku dev reads the credential encryption key from an env var or a runtime-dir file created once with mode 0600, and falls back to in-memory credentials when no database is present
- [A dev run takes PIKKU_ENV from a loopback, non-production environment or leaves it unset](dev-run-takes-pikku-env-from-a-loopback-non-production-environment.md) — pikku dev fills in PIKKU_ENV only when it is unset, choosing a non-production environment whose apiUrl is loopback and preferring one named local, and returns nothing when none qualifies
- [Dev seed and db reset refuse NODE_ENV production and database paths outside the runtime directory](dev-seed-and-db-reset-refuse-production-and-outside-paths.md) — pikku dev seed and pikku db reset throw when NODE_ENV is production, and the SQLite and PGlite reset also refuse a database path outside the runtime directory
- [Dev webhook registrations are refused when git tracks them and gitignored otherwise](dev-webhook-registrations-file-stays-out-of-git.md) — pikku dev refuses to register webhooks when git tracks the registrations file, which holds signing secrets, and appends it to .gitignore when git does not ignore it
- [Every app command lives under `pikku app`](every-app-command-lives-under-pikku-app.md) — Creating, listing and packaging a frontend are all `pikku app …` subcommands — never `pikku new`, never a flag on `pikku deploy`
- [Every middleware registration under a group is imported, not only the primary one](every-middleware-registration-is-imported.md) — The middleware import serializer collects the primary registration and each additional registration for a group, so a second file's auth gate is not skipped
- [Feature flags fail open when unreadable and never gate access, scopes do](flags-fail-open-and-never-authorize.md) — The flag source falls back to every declared flag on when its store cannot be read, and the runtime uses flags for availability only, leaving access to scopes
- [`frontends` in pikku.config.json is the one list of apps](frontends-is-the-one-list-of-apps.md) — The top-level `frontend` key is gone; every frontend — served by pikku, deployed by Pikku Studio Cloud, or packaged as a native app — is a named `frontends` entry in pikku.config.json
- [The generated CLI channel client sends the saved session token to whatever PIKKU_WS_URL names](generated-cli-channel-client-sends-the-saved-session-to-ws-url.md) — When run directly, the generated channel client takes its socket URL from PIKKU_WS_URL, prefers PIKKU_API_KEY, and otherwise sends the human session token from the session file
- [Git push credentials travel through the environment and a credential helper](git-push-credentials-travel-through-the-environment.md) — pushWithCredential passes the username and password as environment variables read by an inline credential helper, so they stay out of argv, the remote URL and .git/config
- [MySQL scratch migrations need the configured role to hold CREATE and DROP on databases](mysql-scratch-needs-create-and-drop-on-the-role.md) — withScratchMysqlDatabase creates and drops a throwaway database on the configured server, so the role must hold CREATE and DROP on databases
- [Adding a session requirement to an existing wiring is a breaking surface change](newly-required-auth-is-a-breaking-surface-change.md) — The surface diff marks a removed wiring as breaking, an added one as not breaking, and a modified one as breaking only when it newly requires auth
- [OAuth token secrets inherit optionality from their app secret](oauth-token-secrets-inherit-optionality-from-the-app-secret.md) — In the generated secrets types, an OAuth2 token secret is optional exactly when its app credential secret is optional, so a deployment that may omit the app is never asked for tokens
- [One identifier per app, on every platform, unique across apps](one-identifier-per-app-on-every-platform.md) — `native.identifier` is the macOS/iOS bundle id and the Android package name at once; it must be Android-safe and no two frontends may share one
- [Only the production flag of each environment ships in the workflow bundle](only-the-production-flag-ships-in-the-workflow-bundle.md) — serializeVirtualUsers projects each environment down to its production flag, so the deployed bundle does not carry apiUrl or paths from pikku.config.json
- [Page screenshots run as a virtual user by reusing the scenario sign-in](page-screenshots-run-as-a-virtual-user-through-the-scenario-sign-in.md) — pikku pages screenshot with --as mints a sign-in statement and resolves the scenario browser provider for the virtual user, instead of an anonymous browser
- [Pikku owns named files and marked regions of a native project, and nothing else](pikku-owns-marked-regions-of-the-native-project.md) — `src/pikku.rs`, `capabilities/pikku*.json`, the two marked plugin blocks in Cargo.toml and four tauri.conf.json keys are rewritten on every run; everything else in src-tauri/ is written once and then belongs to the user
- [The CLI loads the project env file without overriding a real environment variable](project-env-file-never-overrides-real-variables.md) — The pikku entry point reads .env from the working directory, and its fallback parser assigns only variables not already set, so a real environment variable wins
- [The remote job inbox is auth-false, guarded by a secret that fails closed](remote-job-inbox-is-network-open-behind-a-fail-closed-secret.md) — The generated /__pikku/queue-job and /__pikku/scheduler-job routes skip pikku auth and rely on remoteJobsSecret, which rejects every call when the secret is unset
- [Only roles prune removes an undeclared system role](roles-prune-is-the-only-path-that-removes-roles.md) — roles audit and roles prune both read the declared set, but only prune deletes, and only with --yes; audit points the person to prune
- [A deploy unit receives the rpc catch-all only when it contains an exposed function or route](rpc-catch-all-follows-the-exposed-functions-in-a-unit.md) — Per-unit codegen adds the rpcCaller and /rpc/:rpcName entries only when the unit holds an exposed function or an /rpc route, and the remote handler only for remote ones
- [Run telemetry writes the session user and org ids on every wire](run-telemetry-records-session-user-and-org-ids.md) — The outer telemetry middleware writes tenantuserid and tenantorgid from the wire session on every request it times
- [A running project reads secrets from Vault and cannot write them](running-projects-read-secrets-from-vault-and-never-write-them.md) — VaultSecretService authenticates with PIKKU_VAULT_TOKEN over a unix socket, reads values, and throws on set and delete, pointing at Pikku Studio
- [scaffold console fails codegen unless the project declares pikkuBetterAuth](scaffold-console-needs-better-auth.md) — The console functions generator throws when scaffold.console is on and no pikkuBetterAuth config is found, because every console RPC requires a session
- [A scenario database reset is refused unless its target is a loopback host](scenario-database-reset-requires-a-loopback-target.md) — The scenario reset replaces database rows, so the CLI refuses it for a production environment or a non-loopback API URL, and the baseline capture refuses a non-loopback MySQL or Postgres connection string
- [Scenario instrumentation is registered only by the dev server, sessionless with auth true](scenario-instrumentation-is-registered-only-by-the-dev-server.md) — The coverage, stub and grading endpoints are registered at runtime by registerScenarioInstrumentation, not scaffolded, and each one answers for its own session
- [Schema codegen hands the auth factory a placeholder secret service, so migrations never need the real secrets](schema-codegen-hands-the-auth-factory-a-placeholder-secret-service.md) — The Better Auth schema introspection behind db migrate gives the auth factory a fake secret service that resolves every key to a placeholder, so no real secret value is read
- [The generated useSession hook does not disable the Better Auth cookie cache](session-hook-leaves-the-cookie-cache-enabled.md) — The generated session hook fetches get-session with no cookie-cache option, so an ordinary cached read is what refreshes an expired session cookie
- [A shared-secret addon exposes only its GET functions to callers](shared-addon-mode-exposes-only-get-functions.md) — install-addon exposes every function in per-user modes, but in shared mode only the functions whose body calls the GET method, and writes auth true into the wiring file
- [A skill agent's read-only or writer role is derived from its tool list, not declared](skill-agent-role-is-derived-from-its-tools.md) — The skill agent generator sets acceptanceRole from whether the declared tools include a mutating tool, so the role and the tools cannot disagree
- [The stateless session middleware is global, not HTTP middleware](stateless-session-middleware-is-global-not-http.md) — When cookieCache is on, the generated session middleware is registered with addGlobalMiddleware, so it runs for MCP and other non-HTTP wirings too, and passes straight through when there is no request
- [A studio header token must be at least 32 characters](studio-header-token-must-be-at-least-32-characters.md) — registerStudioSession installs nothing when PIKKU_STUDIO_TOKEN is unset or shorter than 32 characters, and otherwise grants a pikku:console session only to a matching x-pikku-studio header
- [The authorization surface is generated as its own import, not on the function leaf](the-authorization-surface-is-generated-as-its-own-import.md) — The CLI emits permissions, auth gates and credential definitions in a separate generated file, so writing a function never decides who may call it
- [The CLI reaches the TypeScript compiler only through a dynamic import](the-cli-reaches-the-compiler-only-through-a-dynamic-import.md) — Every command loads the whole CLI graph, so a static import of @pikku/inspector, @pikku/n8n-import, the @pikku/code-edit root or the mocks stub scanner puts typescript on the startup path of pikku --help; those are imported inside the function that needs them, and eager values come from @pikku/inspector/lite
- [The dev agent runner takes the complete OpenAI pair before the LiteLLM pair](the-dev-agent-runner-takes-the-openai-pair-before-the-litellm-pair.md) — createDevAgentRunner pairs each base URL with its own key, prefers a complete OPENAI_BASE_URL and OPENAI_API_KEY pair, falls back to the LITELLM pair, and leaves agents disabled when neither is complete
- [The studio session middleware is installed by the dev server only, not by serve](the-dev-server-alone-installs-the-studio-session.md) — The dev command registers the studio session middleware after bootstrap, while the serve command only sets the quick-login default and disables dev virtual user sign-in
- [The dev server's content JWT must be the same instance the transport verifies signed reads with](the-dev-server-content-jwt-must-be-the-transports-verifier.md) — DevServerOptions.contentSigningJWT signs asset URLs and the node transport verifies signed reads with it, falling back to the singleton jwt, and refuses signed reads with a 403 when no JWT is available
- [The generated realtime client holds no auth token and delegates it to the shared PikkuFetch](the-realtime-client-holds-no-token-of-its-own.md) — setAuthorizationJWT and setAPIKey forward to the PikkuFetch instance the client was given, so the token lives in one place
- [The services map requires agentRunService whenever the agent scaffold is on and the project has agents](the-services-map-requires-agent-run-service-when-the-agent-scaffold-is-on.md) — The generated public-agent permission destructures agentRunService after the inspector has run, so pikku services adds it to the required singletons by hand
- [The generated setup wrapper builds services.auth lazily and once from the app's authFactory](the-setup-wrapper-builds-services-auth-lazily-and-once.md) — pikkuServices attaches an auth service that runs the app's authFactory on first use, caches the instance, and clears the cache when the build fails
- [The generated isThreadOwner check denies a missing thread the same as a foreign one](thread-owner-check-hides-missing-threads.md) — The public agent's thread ownership permission returns false when the thread does not exist, so a caller cannot tell a missing thread from another user's
- [An addon secret read the inspector cannot resolve is absent from the package](unresolved-addon-secret-reads-need-global-secrets.md) — The package generator builds the declared secret set from definitions and resolved usage keys, so a computed secret id is missing unless the addon sets globalSecrets
- [An unset virtual user mail domain is virtualuser.invalid](unset-virtual-user-mail-domain-is-virtualuser-invalid.md) — When a project names no mail domain, virtual user addresses land on virtualuser.invalid, a domain no one can own, so a send fails instead of reaching a stranger
- [pikku validate forces the two promise rules to error so an un-awaited webhook verify is caught](validate-forces-the-promise-rules-to-error-for-webhook-verify.md) — The validator requires typescript/no-misused-promises and typescript/no-floating-promises at error with type information, because a forgotten await on an async verify helper accepts every request
- [Validate warns when virtual users are declared but no source wires their sign-in](validate-warns-when-virtual-users-exist-but-nothing-wires-their-sign-in.md) — runVirtualUserChecks counts virtual user sign-in as wired only when a pikkuVirtualUser or virtualUser call alongside @pikku/better-auth, or a sign-in/virtual-user route, appears in the project source
- [A virtual user that cannot run where it says stops generation](virtual-user-environment-errors-stop-generation.md) — Virtual user generation throws on environment errors before writing any file, and deletes the secrets file earlier versions generated
- [Virtual user roles are checked against code-declared roles only](virtual-user-roles-are-checked-against-code-declared-roles.md) — The virtual user roles type is SystemRoleName, generated from defineSystemRole declarations, so a virtual user cannot name a console-made custom role
- [pikku virtual-user run with skip-role-check runs a virtual user whose roles were never verified](virtual-user-run-can-skip-the-role-check.md) — The virtual-user run command takes a skipRoleCheck option, and when it is set the roles are not read back or compared before the first step
- [Virtual-user scheduled ticks are left unwired and run as pikku-platform](virtual-user-scheduled-ticks-are-unwired-and-run-as-pikku-platform.md) — The scaffold splits virtual-user scopes into run, read and schedule, and its scheduled tick runs under a pikku-platform session with virtualUser:run, but nothing wires the tick
- [Virtual user sync provisions only the virtual users the environment rule allows, and keeps runnable false ones](virtual-user-sync-provisions-only-what-the-environment-allows.md) — pikku virtual-user sync applies the same environment refusal that decides who may run, and lists a runnable false virtual user anyway because its account is the reason it was declared
- [The webhooks command never handles provider signing secrets](webhook-lifecycle-command-never-handles-signing-secrets.md) — The webhooks check, setup and teardown commands pass only the URL, label prefix and previous state to the app, and print one JSON line per source
- [A trigger webhook receive is public and runs only from its source's route, never as an RPC](webhook-receive-is-public-and-runs-only-from-its-source-route.md) — pikkuWebhookReceive forces auth false, and its func receives services with secrets omitted, so a receive can run only through its source's route
- [A wireAddon credential mode is applied at codegen, not at runtime](wire-addon-credential-mode-is-applied-at-codegen.md) — pikku-command-credentials resolves wireAddon mode overrides into the credentials meta file, so the console reads the final mode from disk
- [Inspector parity runs on every example, template and verifier](inspector-parity-runs-on-every-project.md) — pikku inspector parity runs codegen with both inspectors and fails unless the saved state, the generated files and the diagnostics match; CI runs it on every project in the repo, so a fix covered by a verifier is covered for both engines
