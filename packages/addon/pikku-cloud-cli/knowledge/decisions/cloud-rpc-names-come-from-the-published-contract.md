# pikku cloud rpc names and types come from the published cloud API contract

Production serves the cloud API functions as `cloud:<name>` (the controlplane's
`cloud-api.wiring.ts` wires `@pikkustudio/addon-cloud-api` as `cloud`). The CLI
used to carry a stale hand copy of an old generated SDK with bare names, and a
hand-kept prefix list to correct them at call time. Both are gone.

- `src/contract/cloud-api-types.ts` and `cloud-api-meta.ts` are generated by
  `bun run sync-contract` (`scripts/sync-contract.ts`). It asks the registry
  (`POST /rpc/registry:resolveSdk`, public read, the same call `wireRemoteAddon`
  sync makes), verifies the download against the registry's sha512 integrity,
  and writes the rpc map types plus the contract's function list, version and
  contract hash. Offline: `--tarball <file>.sdk.tgz`; pin: `--range <version>`.
- `cloudRpcName` (`src/lib/rpc-client.ts`) prefixes `cloud:` for every function in
  that list. A name in no list throws instead of being sent to a 404.
- Four calls are not in the contract and are typed by hand in
  `src/contract/uncontracted.ts`: `requestCliAuth`, `pollCliAuth`, `submitFinding`
  (served bare, they live in the controlplane's api-functions package) and
  `createSandboxChange` (`machine:`, in `@pikkustudio/addon-machine-api`, which
  publishes no SDK). Delete an entry once its source publishes a contract.

**Refresh when** the controlplane publishes a new cloud-api version the CLI needs.
`src/lib/http.test.ts` scans the CLI source for every function it invokes and
checks its URL form, so a call the contract lacks fails the test.

**Gotcha:** the registry serves the published version, which can trail the
controlplane's working tree. The CLI is typed against what is published.
