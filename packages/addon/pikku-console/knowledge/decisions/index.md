# Decisions

<!-- pikku:knowledge-index -->
- [Agent credential status is read for the caller's own session user only](an-agent-credential-check-reads-only-the-callers-own-session.md) — agentCredentialCheck takes the user id from the session and never from input, so a caller cannot probe another user's connected credentials
- [Agent run grades are readable by the run's owner or the admin root, and a hidden run reads as not found](console-agent-run-scores-hides-runs-the-caller-cannot-see.md) — get-agent-run-scores declares no scopes; it checks the admin root or canAccessThread in the body and throws NotFound for both a missing run and a run the caller may not see
- [Thread run listings filter other owners' runs out instead of refusing, and the admin root sees all](console-agent-thread-runs-are-filtered-not-refused.md) — get-agent-thread-runs returns every run to the admin root and filters the rest by canAccessThread, so an empty list never confirms that another owner's thread exists
- [Console functions are each gated by one declared pikku:console scope, with no role check in the body](console-functions-are-gated-by-one-declared-scope.md) — Most console functions declare exactly one pikku:console:* scope in scopes and check no role in the body; ping and get-agent-run-scores declare no scopes at all
- [The console git push uses the developer's own git credentials, cannot prompt for them, and runs only where a git service is wired](console-git-push-uses-the-local-git-environment.md) — push-git-changes delegates to gitService.push, which runs git with every credential prompt disabled, so the push uses credentials already set up on the machine
- [A second install of the same addon namespaces its secret, variable and credential names](console-instance-overrides-namespace-a-second-install.md) — install-addon derives per-instance overrides only when the package is already wired, prefixing env-style secret and variable names with the namespace and prefixing credential names with it
- [Page screenshots exist only where a project meta path is present, and each page is captured signed out](console-page-screenshots-need-a-project-and-sign-out.md) — pageScreenshotService is constructed only inside the metaBasePath branch, so screenshot-pages throws LocalEnvironmentOnlyError elsewhere; the service opens each page without a session
- [The console ping probe declares no scopes, so the UI learns whether the addon is wired](console-ping-probe-carries-no-scopes.md) — ping returns { pong: true } with no scopes; its comment says an unwired addon 404s while a wired one answers 200, 401 or 403, and that 401 and 403 both mean wired
- [Console secret plaintext is revealed in one place, SecretAdminService.read](console-secret-plaintext-is-confined-to-one-reveal-call.md) — SecretAdminService is the only console code that calls reveal() on a secret, so the plaintext disclosure can be found by grepping for one call; secretGet returns that read under pikku:console:secrets:read
- [A database column with no privacy annotation is classed private](console-unclassified-db-columns-are-private.md) — classificationFor passes through only public, private, pii and secret, and returns private for anything else, including a column with no annotation
- [The console wiring snapshot carries virtual users, system roles and scope trees, and the addon filter does not narrow them](console-wiring-snapshot-ships-virtual-users-roles-and-scopes.md) — AllMeta includes virtualUsers, systemRoles and scopes; get-all-meta returns them under pikku:console:wirings:read, and filterAllMetaByAddon narrows the wiring lists but spreads these three fields through unchanged
- [The wish-deck generator sends whatever key and URL it is given as a bearer token](console-wish-deck-sends-the-model-key-to-the-access-url.md) — generateWishDeck posts to access.proxyUrl with access.apiKey as a Bearer header and checks no host; the studio host builds that access object from env or from the Pikku Studio Cloud LiteLLM key
- [Deleting an agent thread needs the agents:manage scope and the thread owner check, which only the admin root skips](deleting-an-agent-thread-needs-the-scope-and-the-thread-owner-check.md) — deleteAgentThread declares the console agents:manage scope and an owner permission, so holding the scope alone does not let a caller delete someone else's thread
- [Scenario artifacts are served by a route-only function, and the run store refuses escaping paths](scenario-artifacts-are-served-by-a-route-only-function.md) — getScenarioArtifact is not RPC-exposed and returns raw bytes over HTTP; it passes the client's path to the run store, and the file store rejects ids and paths that would leave the run
- [The studio host uses the CLI's Pikku Studio Cloud token, and a linked project always routes model calls through the developer's LiteLLM key](studio-host-uses-the-cli-cloud-token.md) — resolveStudioHost takes the cloud token from the CLI context; when a project is linked, models come from getDeveloperLiteLLMKey whatever PIKKU_STUDIO_AI is set to, and only an unlinked project reads the flag
- [The local OAuth2 mock server hands out fixed test credentials](the-local-oauth-mock-server-hands-out-fixed-test-credentials.md) — The test OAuth2 server listens on localhost, generates a fresh RSA key on each start, and prints a fixed client id and secret for local use
- [Virtual-user runs and schedules are read from the host's stores, so reading needs no scaffold](virtual-user-reads-come-from-the-host-stores-not-the-scaffold.md) — get-virtual-user-runs, get-virtual-user-run-steps and get-virtual-user-schedules read the host's own run and schedule stores directly, so a project shows its history whether or not scaffold.virtualUser is on
- [Virtual-user run records and transcripts are a privileged read with a row ceiling in the function](virtual-user-run-reads-are-privileged-and-row-capped.md) — Run records and turn transcripts sit under their own read scope rather than the wirings scope, and the page size is clamped in the function because the input type is not checked at runtime
- [Starting a virtual-user run or changing a schedule delegates to the scaffold, under its own scope](virtual-user-writes-delegate-to-the-scaffold-under-their-own-scopes.md) — start-virtual-user-run and set-virtual-user-schedule dispatch to the project's scaffolded functions rather than writing rows, and each has a scope separate from reading
