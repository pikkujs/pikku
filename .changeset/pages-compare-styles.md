`pikku ui pages compare` compares style as well as pixels: where the reference has `<id>-<width>.style.json` (written by the pikku-site-clone capture), it reads the same summary from our page (page background, header height and background, h1/h2/h3, first paragraph and primary button: size, weight, colour, alignment, font, background; text column width) and prints up to six differences that matter per page, worst first, in plain words (`h1: original 56px 700 #a3132f center; yours 40px 300 #111111 left`), also in report.json rows as `styles`. Reference ids `home` and `index` map to `/`, and the default output directory is `artifacts/tmp/compare/<app>`. The capture dismisses cookie/consent banners, loads lazy sections by scrolling slowly and forcing lazy pictures, and photographs phone widths with an iPhone Safari user agent (isMobile, hasTouch), zoomed to the phone width when the mobile page lays itself out narrower. `pikku changes done` accepts `--waive` only for phone widths (under 1000 px) with a reason of 30+ characters; a desktop width over the threshold is refused with its numbers and style differences. The gate reads the report from `artifacts/tmp/compare/<app>` and still from `.pikku/pages/compare/<app>`. The pikku-site-clone and pikku-changes skills say to fix the style lines first, open the diff of the worst page, and waive only phone widths.
