# Decisions

<!-- pikku:knowledge-index -->
- [A banned user is refused at session creation and the ban lapses on expiry](a-banned-user-is-refused-at-session-creation-and-lapses-on-expiry.md) — The pikku ban plugin refuses a session for a banned user at creation, clears an expired ban only when that happens, and a ban written by an admin ends existing sessions at once
- [A credential link is keyed by the linking user and never signs anyone in](a-credential-link-is-keyed-by-the-linking-user-and-never-signs-anyone-in.md) — Connecting an OAuth credential stores its account row under the linking user's id rather than the provider's identity, and the callback refuses any flow that is not a link
- [A delegated login never claims an existing user by a synthetic email](a-delegated-login-never-claims-an-existing-user-by-a-synthetic-email.md) — Upstream login attaches to an existing user row only when the app opts in and the upstream itself returned that email, never to an administrator unless the app allows it, and never to a virtual user row or a user already bound to another upstream identity
- [A delegated login stores the upstream credential before the session](a-delegated-login-stores-the-upstream-credential-before-the-session.md) — If the upstream token cannot be persisted the sign-in fails outright, because every proxied call would be dead on arrival, and passwords are never stored
- [A live session is checked before a session middleware resolves one](a-live-session-is-checked-before-a-session-middleware-resolves-one.md) — The middlewares read the session the chain has set so far, not the wire snapshot, so an earlier middleware's session is never overwritten by the default mapping
- [A session middleware stands down where it cannot authenticate](a-session-middleware-stands-down-where-it-cannot-authenticate.md) — Global middleware runs on addon dispatches too, and an addon's scope deliberately withholds the host's auth secret and auth instance — so the absence is the normal case, not a fault
- [A session read that fails is an error, not anonymous](a-session-read-that-fails-is-an-error-not-anonymous.md) — Only a genuinely absent session falls through to anonymous; a failed read or a failing caller hook rejects the request so an outage cannot look like a logged-out user
- [A singleton credential belongs to a reserved platform user behind an admin scope](a-singleton-credential-belongs-to-a-reserved-platform-user.md) — A credential shared by the whole app is owned by the reserved pikku-platform user, and only a caller holding admin:credentials:link may connect it
- [A store-backed session is signature-checked before the store is read](a-store-session-is-verified-before-the-store-is-read.md) — betterAuthStoreSession rejects an unsigned or forged credential before any store lookup, and signing out deletes the store entry so revocation is immediate on both transports
- [Admin capabilities fail closed without a scope service](admin-capabilities-fail-closed-without-a-scope-service.md) — With no ScopeService registered, the admin gates deny everyone and log a configuration warning, so a missing wiring cannot grant impersonation or singleton credential links
- [An admin-created user is removed when its password cannot be linked](an-admin-created-user-is-removed-when-its-password-cannot-be-linked.md) — createAuthUser checks the password policy first and deletes the new user if the credential account write fails, because the two writes have no shared transaction
- [An API key header is authoritative for its request](an-api-key-header-is-authoritative-for-its-request.md) — When the key header is present the middleware never falls back to the cookie session, and a key-minted session can be restricted to a set that is never widened back to the owner's rights
- [An impersonated session runs with the target's rights](an-impersonated-session-runs-with-the-targets-rights.md) — Once impersonation resolves, scopes are fetched for the target user id, so the admin's own grants never carry over to the impersonated request
- [An invitation is a magic link to an existing account](an-invitation-is-a-magic-link-to-an-existing-account.md) — sendAuthUserSignInLink uses the magic-link plugin with sign-up disabled, so an invite can only reach an address that already has a user row and needs no invitation table
- [An unconfigured OAuth provider is skipped and a malformed one throws](an-unconfigured-oauth-provider-is-skipped-and-a-malformed-one-throws.md) — A credential whose app secret is absent is left out with a warning so one missing provider cannot break every session read, while a secret that exists but has no clientId still fails
- [An impersonation header nobody honours is reported once](an-unhonoured-impersonation-header-is-reported-once.md) — A request carrying the impersonation header to a middleware without the option logs one warning per process, because scenario runs send the header on every request
- [An unknown upstream role does not fail the sign-in](an-unknown-upstream-role-does-not-fail-the-sign-in.md) — A role the app has not defined is dropped with a warning and the user signs in without it, because a provisioning gap should not lock out someone who proved access
- [Cross-site cookies are relayed only when the runtime embeds apps](cross-site-cookies-are-relayed-only-when-the-runtime-embeds-apps.md) — A third-party iframe needs SameSite=None cookies and, on WebKit, a JavaScript-held relay; both switch on only under AUTH_COOKIE_CROSS_SITE, so a deployed app keeps its Lax cookies and ignores the relay header
- [Dev quick login refuses proxied and non-loopback requests](dev-quick-login-refuses-proxied-and-non-loopback-requests.md) — The dev admin sign-in uses a per-process random password, is judged by the raw Host and Origin headers, is refused whenever a proxy-forwarding header is present, and is never on in production whatever the flag says
- [Impersonation is opt-in and gated by the admin impersonate scope](impersonation-is-opt-in-and-gated-by-the-admin-impersonate-scope.md) — The impersonation header is ignored unless the app passes the option, and the default gate admits only a caller whose ScopeService grants admin:impersonate
- [Only pikku dev may create virtual user accounts](only-pikku-dev-may-create-virtual-user-accounts.md) — A deployed stage that opens virtual user sign-in can sign in only as virtual users already provisioned there, because minting a new virtual user row is allowed only under pikku dev
- [Provisioning a returning virtual user lifts its ban](provisioning-a-returning-virtual-user-lifts-its-ban.md) — When a virtual user is declared again and its account is banned, provisioning unbans it, so a re-declared virtual user is not left unusable with no visible reason
- [The console scope root is separate from the admin root](the-console-scope-root-is-separate-from-the-admin-root.md) — auth-scopes.ts declares the console's own root, pikku:console, beside admin, so holding the admin grant never opens the console
- [The OAuth proxy is all or nothing and never overrides the app's own providers](the-oauth-proxy-is-all-or-nothing-and-never-overrides-the-apps-own-providers.md) — A stage that carries part of the OAuth proxy configuration fails at boot, and a provider the app configures itself cannot also be routed through the proxy
- [The stateless middleware is told how the cookie was written](the-stateless-middleware-is-told-how-the-cookie-was-written.md) — betterAuthStatelessSession never builds the auth instance, so a custom cookie prefix and a cookie-cache version are passed to it, a jwe or jwt strategy is recognised from the cookie's shape, and pikkuBetterAuth reports a mismatch
- [The stateless session cookie gets a one-day lifetime unless the app sets one](the-stateless-session-cookie-gets-a-one-day-lifetime-unless-the-app-sets-one.md) — With betterAuthStatelessSession in use, a cookie cache left at better-auth's 300 seconds would sign users out five minutes after login, so pikku inserts a day or a stage variable's value
- [The virtual user sign-in gate stays shut unless dev or the exact opt-in value is set](the-virtual-user-sign-in-gate-stays-shut-unless-dev-or-the-exact-opt-in-value.md) — Virtual user sign-in opens only under pikku dev or when PIKKU_ALLOW_VIRTUAL_USER_SIGN_IN holds the one exact value, a near-miss value is warned about without being echoed, and a shut gate registers no sign-in endpoint
- [User administration is decided by scopes, not a role column](user-administration-is-decided-by-scopes-not-a-role-column.md) — pikku drops better-auth's admin plugin and its role column; each user-admin operation is a plain call, and the admin scope on the calling function is the only gate
- [Virtual user upstream credentials are read from the environment on each sign-in](virtual-user-upstream-credentials-are-read-from-the-environment-on-each-sign-in.md) — The credentials a virtual user carries are taken from VIRTUAL_USER_CREDENTIAL variables at every sign-in, stored per virtual user, and removed when the variable is gone
