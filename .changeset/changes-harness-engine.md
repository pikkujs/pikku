The changes commands and their build harness. `pikku changes next --merge-one` merges one finished changeset per call, so a merge lane can check the main branch after each merge. `pikku changes done` recognises the migrations of every Pikku project in the checkout (each `pikku.config.json` and its `rootDir`), not only a root `db/` folder. `pikku changes done --waive` is removed: whoever runs `done` (a builder too) could waive a phone width, so every width must now pass. The build harness (`@pikku/addon-changes-cli/harness`) runs on the workflow engine: `runHarness` takes the run's `workflow` wire and runs only in a run started with the wire `{ type: 'harness' }`; every agent turn, gate run and commit is an inline step, and a gate's `workflowRetries` are the step's retries. A gate lists the rules of its findings a person may waive (`waivable`; the pages gate's phone widths), and the engine asks for each on `workflow.approval`, from a signed-in user who did not start the run by default; a refused or expired waiver keeps the finding failing. The pages gate no longer reads `waivers` from `artifacts/pages-compare.json`. `tries` defaults to 2, and each tool a gate runs records its duration and exit code as a `harness.cli` analytics event. The pikku-site-clone skill no longer offers `--waive`.
