`pikku changes done` refuses a change that touched pages of a site rebuilt from a reference. When the project has `artifacts/references/<site>/` screenshots and the change set (diffed against the nearest branch point) touched route files of reference pages, `done` needs `<outDir>/pages/compare/<app>/report.json` taken at HEAD with no uncommitted frontend changes, covering every touched page at every reference width, none MISSING, each within `pagesCompare.threshold` in pikku.config.json (default 40%). The refusal names the worst pages and widths with their numbers, the diff images, the widths with no report entry and the `pikku ui pages compare --page <ids>` to run. `--waive "<reason>"` (at least 10 characters) finishes anyway and puts the reason in the done note; `PIKKU_COMPARE_GATE=off` turns the gate off. `report.json` now carries `gitSha`, `dirty` and `generatedAt`, and its default directory is `<outDir>/pages/compare/<app>` (it was joined under the project root twice). `pikku ui pages compare` no longer needs `--baseUrl`: it uses the frontend's dev server from `frontends.<name>.dev`, starting it from the app directory when nothing answers on its port and stopping only what it started; the API is not started, and the output says when it did not answer. `@pikku/cli/addon-support/pages` exposes route discovery and reference reading to addons. The pikku-site-clone and pikku-changes skills say a page change is done only when the compare passes, how to read the diff, and when to waive.
